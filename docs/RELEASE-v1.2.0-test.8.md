# v1.2.0-test.8 · 恢复图标加载与 WebUI 紧凑开关

2026-09-28，版本码 121。本地实测包。

## 应用图标

按用户指定会话“侧键”回查，并与 Apple 界面改版前的 Git 版本 `4697ac9` 对照。旧版通过 `app-icons` 获取本机 PNG，最多 16 张一批，收到后直接将图片插入列表。改版后增加了可见性筛选、独立列表坐标判断，以及等待图片加载事件后才替换占位符的流程。Android 查询接口和 KernelSU 桥接未因 Apple 改版更换。

- 恢复旧版的 16 张分批请求与直接插入 PNG 的方式，加载事件只负责记录成功或提示解码失败。
- 选择器生成列表后，直接请求前 16 个图标，不再以列表高度、行坐标或动画状态作为首批请求的前置条件。搜索、刷新及重新打开同样执行。
- 其余图标恢复旧版 IntersectionObserver 懒加载，并保留滚动、页面切换和动画结束时的可见性补充检查。
- 已选应用和首页快捷栏摘要同步主动请求；继续保留缓存、按当前 Android 用户隔离、取消过期回调、刷新重试和错误提示。
- Android 图标组件沿用 test.7 的系统图标及原应用资源回退，未改动手机原生菜单的图标读取方式。

尚未取得手机上的图标接口回包，不能将某一个前端差异认定为已证实的唯一根因。本版恢复旧路径并去除首屏请求条件，实际显示仍由用户真机确认。

## 补齐 WebUI 紧凑布局

- 接管侧键、触感反馈、减少动态效果采用左标题、右开关的紧凑行；通常高度 58 px，保留至少 44 px 的开关触控区域。正常接管状态不再重复显示，连接中或服务异常仍有提示。
- Surfing 显示项由左侧复选框改为右侧开关，与标题同行，最小行高 48 px。修改仍更新原有显示位掩码，保留保存流程和全部自定义文案。
- 米家手机端设备列表改为 58 px 起的横排项目，名称、图标及详情入口同行，移除常驻在线／离线文字。离线样式与无障碍说明保留；设备目录没有开关读数，不将在线误当作开启。
- 米家布尔属性将已读回的开关状态放在标题右侧，以绿色／灰色电源图标表示；未确认使用减号，不显示重复状态文字。该图标是读回状态，点击行仍展开动作配置，未新增即时控制。
- 米家非布尔读数、单位、云端上报及失效说明保留，固定“开启／关闭”和“切换”仍是可选择的动作，未删减功能。
- 快捷项摘要收紧内边距与图标尺寸。原生快捷菜单继续沿用 test.7 的同行开关和隐藏重复状态文字；Surfing 仅在确认开启且不在切换中时显示详情。

## 安装与实测

在 KernelSU 覆盖安装 `test_oppo_sidekey_v1.2.0-test.8.zip`，重启手机，关闭旧 WebUI 后重新打开，确认设置页版本为 test.8。旧配置、登录、APK 签名与外观偏好保留。

1. 快捷栏 → 应用：检查首屏图标、搜索具体应用、向下滚动、刷新及关闭重开后的图标；勾选后检查已选应用图标。
2. 检查接管、触感、减少动态效果和 Surfing 显示项：标题在左、开关在右；改变后保存并重开，确认配置没有丢失。
3. 米家设备列表检查紧凑横排；打开设备后检查布尔状态图标、原有动作配置和读数卡片入口。
4. 双击原生菜单检查同行开关、未知图标、米家操作后刷新、Surfing 关闭时无统计与开启后展开，试深浅色和窄宽度。

若图标仍失败，请保留应用列表上方完整错误文字；若无报错，记录设置页实际显示的版本。当前不需要 ADB。

## 构建与限制

运行 `python build.py`，执行现有 JavaScript 语法检查、ARM64／Java／API 35 编译、SF Symbols 资源转换、DEX、APK 签名及 ZIP 完整性检查。AppCatalog 已过时 API 提示沿用，实际结果见本次构建日志。

按照项目约定，不运行自动测试、浏览器测试、联网测试或 ADB。原生菜单代码与资源应同 test.7，APK 仅同步版本；交付时比对 DEX、资源和证书。手机显示、触控和图标恢复需要用户实测。本次未推送或发布。
