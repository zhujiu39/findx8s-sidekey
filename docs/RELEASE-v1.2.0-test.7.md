# v1.2.0-test.7 · 应用图标与紧凑开关菜单

2026-09-28，版本码 120。修正 WebUI 应用图标读取路径，并按最新要求调整双击侧键弹出的原生开关卡片和 Surfing 显示逻辑。

## 应用选择页图标

用户确认：双击侧键弹出的原生菜单能显示图标，WebUI 的应用选择页不能显示。两者分别使用原生 Drawable 和 Root 转 PNG 接口，前者成功不等于后者已验证。

- 应用列表改为独立滚动区域，标题、搜索和确认按钮固定在区域外；根据列表自身坐标显式请求首屏、搜索结果和滚动到的图标，不再依赖弹窗在整页中的动画位置。
- 刷新、图标重置、动画结束和尺寸变化后重新检查可见行；继续使用缓存、请求合并、两张一批及取消过期回调。
- 系统样式图标无法转成 PNG 时，尝试从同一应用的原始图标资源读取，并保留原失败阶段。若仍失败，返回具体的系统图标／应用资源错误；不再仅返回无原因的空图标。
- 未在当前用户启动列表中找到的应用有明确提示。图标仍限制为经过校验的本机 PNG，不接受远端图片或 SVG。

尚未取得手机上的图标接口回包，也未进行真机复现。本版覆盖弹窗加载和 PNG 转换两条路径，实际恢复情况需要用户安装后复测。

## 紧凑开关与 Surfing

- 原生菜单开关卡片采用左侧标题、右侧开关的单行布局，窄宽度也不再把开关排到下一行。
- 去掉常驻的在线／离线、已开启／已关闭和轻触执行文字，减少纵向留白与卡片间距，整卡可点区域至少 48 dp。
- 开启显示绿色电源按钮，关闭显示灰色电源按钮，等待与未知使用不同图标；原有禁用规则继续有效。长名称省略显示，长按提示与无障碍信息保留完整名称和状态。
- Surfing 只有在服务确认开启且不在切换中时显示勾选的详细信息。关闭、切换中或状态未知时，速率、累计流量、订阅及说明整体隐藏，不留空白、不朗读旧统计。
- 关闭统计区不会清空显示项和自定义文案；重新确认开启后按原设置显示。操作失败保留一次性反馈。
- 只读卡片继续显示云端上报／最近上报提示，离线或连通状态未确认的读数不伪装为实时测量。

WebUI 的布局预览同步紧凑排列。点按预览中的 Surfing 开关可查看开启后的布局示意，数值使用“—”，不执行实际启停、不写配置。

## 安装与真机实测

在 KernelSU 覆盖安装 `test_oppo_sidekey_v1.2.0-test.7.zip`，重启手机，关闭旧 WebUI 后重新打开，确认版本为 test.7。旧配置、签名证书和米家登录保留，浅色纯白／深色深底／跟随系统保持。

1. 快捷栏 → 应用：检查首屏图标，向下滚动，再搜索具体应用；刷新、关闭重开后检查图标和勾选内容。若有错误，记录列表上方的完整错误提示。
2. 检查 WebUI 已选应用和双击原生菜单里的图标，并试小窗启动。
3. 在 Surfing 关闭时打开菜单：应只显示标题与右侧开关，不显示统计或占位；启动并确认开启后才展开详细内容；关闭后立即收起，重新开启仍保留原勾选项和文案。
4. 检查手电筒、米家和 Surfing 卡片的标题与开关在同一行；试窄宽度、长名称和深浅色，核对离线／未知仍使用正确图标和禁用规则。
5. 米家读数、场景和普通动作入口保留；检查温度等读数以及失败反馈。WebUI 的 Surfing 布局预览仅演示布局，不应实际启停代理。

## 构建范围

运行 `python build.py`，执行 JavaScript 语法、71 项 SF Symbols 来源与资源转换、ARM64／Java／API 35 编译、DEX、APK 签名和 ZIP 完整性检查。Java 编译仍会报告 AppCatalog 使用已过时 API，详细结果保留在构建日志。

按项目约定不运行自动测试、浏览器测试、联网测试或 ADB。实际图标、菜单布局、触控和服务控制由用户真机验收；本版没有发布到 GitHub。
