# v1.2.0-test.4 · WebUI 图标与米家加载修复

版本码 117。本版处理 test.3 真机反馈的两个 WebUI 问题，保留现有 Apple 风格、配置格式、账号数据和菜单 APK 签名。

## 米家加载

页面改版后移除了账号状态圆点，状态更新脚本仍访问它的 `classList`，导致后续家庭和设备加载中断。本版恢复真实账号状态圆点，并允许装饰元素缺失时继续加载业务数据。

该问题无需退出米家账号或重建绑定；原有登录、家庭、设备、场景、读数及已配项目继续使用原接口。

## 应用图标

针对 WebUI 的应用选择列表／快捷栏编辑页只显示占位、没有错误提示的反馈：

- 主动检查可见图标，切页、弹窗、滚动与窗口变化后补充加载；不再依赖 WebView 的 IntersectionObserver 通知。
- 应用列表初始化或刷新后恢复现有图标请求，避免早期排队请求被清掉后一直显示占位。
- 相同应用共享请求；每批最多读取两张 72 px PNG，成功图标缓存上限 128 项。
- 只有图片成功解码后才替换占位；失败不缓存为空字符串。应用选择和快捷栏页显示具体的读取或解码错误，可刷新重试。
- 刷新、删除元素或切换 Android 用户后，旧请求不能回填到新图标上。

本次不修改 Android 图标提取接口和原生快捷栏。图标仍来自手机安装的应用；缺失时 SF Symbols 仅作占位。

## 安装与复测

在 KernelSU 覆盖安装 `test_oppo_sidekey_v1.2.0-test.4.zip` 并重启，重新打开 WebUI。

1. 进入“快捷栏 → 选择应用”，确认首屏显示实际应用图标；搜索、滚动后查看新出现的项目。
2. 点击弹窗“刷新”，确认图标重新加载，勾选草稿保留。回到快捷栏编辑页，确认已选应用图标正常。
3. 进入米家页，确认不再出现 `classList` 报错，账号、家庭、设备、场景和已配置项目可加载；检查账号管理能打开。

如果图标仍显示占位，记录页面的新提示原文；本版区分系统未返回图标、命令／数据异常和 PNG 显示失败，便于继续定位。

## 验证边界

按项目约定使用 `python build.py` 进行 WebUI 语法、ARM64／Java／API 35 编译、D8、APK 签名及安装包完整性检查。没有运行自动测试、浏览器测试、联网测试或 ADB。

米家空引用原因已在源码中确认。未取得手机图标请求回包，本版修复已识别的前端加载缺陷并补充错误信息；两个问题的真机恢复情况仍需用户确认。实际编译结果见同目录的 `构建日志.txt`。
