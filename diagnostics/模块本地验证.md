# 侧键自定义 v0.3.0 本地验证

日期：2026-09-16。用户选择自行安装，本次没有连接或操作手机。

## 本次变更

- 新增 torch 内置动作，升级保留配置，旧 Shell 由用户在 WebUI 中手动切换。
- Java app_process 调用 CameraManager，选择支持闪光灯的后置相机，使用系统公开的最高亮度档位；单档设备使用系统默认亮度。
- 通过 TorchCallback 获取系统真实状态；不写 sysfs，不修改 flashlight_enabled 等状态设置项。
- 原生监听服务按配置管理 Java 子进程，通过 PR_SET_PDEATHSIG 绑定父子进程退出；动作子进程仅请求切换，不承载灯光所有权。
- 本机抽象 Unix 套接字只接受 UID 0，单字节请求与限长换行响应。仅在发送前等待服务，不重发已提交请求。动作总等待 8 秒；Java 初始化和相机请求另有超时退出保护。
- WebUI 展示开关、实际亮度／上限、相机占用及错误日志；手电筒日志限制为约 64 KiB，页面显示末尾约 6 KiB。

## 本地验证

- ARM64 静态 ELF 编译，-Wall -Wextra -Werror；无动态解释器，加载段按 16 KB 对齐。
- Java 编译使用 Android API 35 接口库，D8 生成最低 API 33 的 DEX；模块安装目标仍为 Android 15 及以上。最终构建无编译警告。
- 纯 Java 逻辑测试：最高亮度、重复开关、外部开关状态同步、相机不可用、初始状态超时、回调超时、不重复请求、API 失败不伪造状态、单档设备、异步回调确认。
- 9 类 C 手势测试及配置／十六进制校验通过。
- 8 项 JavaScript 测试通过，覆盖新 torch 动作参数和原有 KernelSU 回调协议模拟。桥接模拟不代表手机管理器已通过实测。
- WebUI 序列化 → 实际 C 配置解析 → JSON 往返，覆盖 torch 动作及含中文、引号、换行的旧 Shell。
- Shell 和 JavaScript 语法、文本 UTF-8／LF、ELF、DEX 和 ZIP 内容校验。
- 浏览器 390×844 预览：长按选择“切换手电筒（系统最高亮度）”，无需填写 Shell；未保存提示及“系统手电筒”诊断行存在，无浏览器控制台错误。预览不模拟真实手机灯光。
- 人工检查：子进程 exec 关闭继承的输入设备和监听锁描述符；服务失败不会阻塞按键主循环；原始已发送切换请求不自动重试。

每次交付目录中的“构建日志.txt”是该次实际重新构建和测试的输出。Windows 本地未运行 ARM64 监听程序，因此进程清理、Unix 套接字和 CameraManager/ColorOS 集成仍在实机验证范围。

## 已有设备证据

之前从手机读取的侧键：gpio-keys、Linux 键码 735（0x02DF）、按下 1／松开 0，详见同目录侧键识别记录。

用户反馈旧脚本可以切换硬件灯光，但亮度偏低且控制中心不更新。这只验证旧脚本的硬件节点有效，不代表 v0.3.0 的系统接口已经通过测试。

## 安装后需要确认

1. 升级前先用旧脚本关灯，覆盖安装 v0.3.0 并重启。
2. WebUI 将长按改为内置手电筒动作，保存后等待几秒，确认服务能初始化以及上限档位。
3. 长按开灯，观察亮度和控制中心图标；再次长按关灯。
4. 从控制中心手动开／关灯，再长按，确认按实际状态反向切换。
5. 检查相机占用、锁屏、息屏、禁用模块、重启与卸载。
6. 失败时提供 WebUI 的“系统手电筒”状态及完整手电筒日志；不放宽 SELinux，也不改回猜测的硬件亮度值。

ColorOS 对 root app_process 的调用策略、具体亮度档位、控制中心行为和睡眠唤醒只能通过本机安装验证；本地自动化不能替代这些检查。
