## 构建交付

默认只编译、签名和打包，由用户实机测试：

```powershell
python build.py
```

每次是否执行测试以交付目录中的构建日志为准。仅在用户明确要求自动验证时执行：

```powershell
node --test tests/*.test.js
python build_mijia.py --test
python build.py --test
```

| 范围 | 检查内容 |
| --- | --- |
| 输入与配置 | 手势时序、配置边界、旧配置升级、中文与大配置跨语言往返 |
| 快捷菜单 | 横竖屏、安全边距、120～360 dp 宽度、0～32 dp 间距、隐藏项与索引一致性 |
| 系统动作 | 手电筒状态同步、小窗接口与启动确认、超时与单次提交 |
| 米家 | 认证隔离、规格与参数校验、在线状态与离线拦截、单设备刷新、状态滞后、有限次读回与日志脱敏 |
| 日志 | 全部分段与轮换文件、完整导出、UTF-8、长度与 SHA-256、取消与写入失败 |
| 产物 | ARM64 ELF 及 16 KiB 对齐、DEX、APK 签名、脚本语法、ZIP 内容与权限 |

米家自动测试使用合成设备，不需要真实账号。可选 `python build_mijia.py --live` 检查匿名扫码握手与公开设备规格；它不验证登录后的设备控制。

## 真机验收

1. 覆盖安装并重启，确认已有配置、侧键接管和震动正常。
2. 检查菜单横竖屏、系统深浅色、宽度和间距；开关点击后保持展开，应用点击后收起并以小窗打开。
3. 米家登录、选择家庭并添加动作；分别观察实体设备、快捷栏图标和最近执行结果。
4. 设备离线时第二行显示离线且不能操作；恢复后重新打开菜单可刷新。操作某台设备时，其他设备的显示保持不变。状态滞后时应等待读回目标值；控制不自动重发，空闲时不持续读取云端。
5. 导出完整日志，选择位置后检查文件末尾的 `SIDEKEY_LOG_END`；取消导出不应报告保存成功。复制日志也应可用。

每次交付的具体命令、结果和编译提示见该目录的 `构建日志.txt`。真机问题反馈应包含模块版本、操作时间、实体设备表现及导出的日志，不提供登录凭据或二维码。
