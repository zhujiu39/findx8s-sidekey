# 侧键自定义 v0.5.2 本地验证

日期：2026-09-21。本次聚焦透明背景、按配置显示和布局调节；没有连接或操作目标手机。用户已反馈 v0.5.1 使用良好，本版沿用其 ColorOS 仅小窗启动实现。

## 问题依据与修正

- 原菜单绘制了全屏半透明黑色 View，弹出后会压暗当前应用。本版删除该 View 及动画，同时关闭窗口背景压暗；面板本身继续跟随系统深浅色。
- 原生组件固定补齐两个开关和空应用提示。本版按已配置动作生成展示列表，过滤“不执行动作”；全部为空时 Root 服务直接结束菜单请求，不启动空 Activity。
- 筛选时重新建立紧凑展示索引，保留每项与原动作的对应关系。旧配置中的普通应用仍在菜单执行时转换为 ColorOS 小窗。
- 开关取消两个位置限制，与应用一样复用显示行。应用始终为两列，奇数个应用最后一行不补可见卡片，超出窗口时滚动。
- WebUI 新增快捷栏宽度 160～360 dp、应用间距 0～32 dp。设置贯通校验、持久化、JSON 读取、启动参数与原生测量；旧配置缺少字段时使用 196 dp、12 dp。
- 面板仍受当前窗口和系统安全边距约束，宽度不足时自动收窄，横屏限高。

窗口背景压暗的依据见 [Android WindowManager.LayoutParams 文档](https://developer.android.com/reference/android/view/WindowManager.LayoutParams#FLAG_DIM_BEHIND)。

## 自动化检查

- C 配置测试：旧配置默认值、范围上下界、非整数／负数／重复字段拒绝、失败不覆盖有效配置。
- C 菜单快照测试：空列表、全部空动作、前中后穿插空动作、筛选后的动作映射、旧应用转换、最大容量与空指针处理。
- Java 几何测试：160／196／280／360 dp，左右弹出、横竖屏、反向横屏、不同 density、挖孔与导航安全边距、窄窗口与异常宽度钳制。
- 23 项 JavaScript 测试通过，包括布局值范围和旧配置序列化；WebUI → C 原子写入 → JSON 实测回读宽度 280、间距 24。
- 2048 应用配置与分块保存测试通过；原有手势、手电筒状态、应用目录、OPlus 小窗确认和失败不全屏回退测试通过。
- 安装脚本、应用启动脚本、Shell 语法、ARM64 静态 ELF 与 16 KiB 对齐检查通过。
- API 35 菜单 APK 编译、DEX、v3 签名、版本 52 和模块 ZIP 完整性校验通过。

构建入口为 `python build.py`。应用目录入口仍有既有过时 API 编译提示，不影响构建；菜单 APK 的 Java 编译使用 `-Werror`。

## 浏览器界面检查

使用本地模拟应用目录和配置，不读取或操作手机应用：

- 单个手电筒开关、零应用：只显示一个开关，应用区隐藏。
- 三个有效开关、一个空动作草稿、11 个应用：只显示三个开关和 11 个应用，保持两列，内容可滚动。
- 390 × 844 竖屏与 844 × 390 横屏：面板上下留出 12 px，横屏面板高度 366 px，超出部分在栏内滚动。
- 宽度最大值 360 与间距 32：实际应用到预览；窄视口按可用宽度收窄。
- 宽度 160、间距 0、右侧弹出：保存并重新加载后保持一致；零有效开关时开关区隐藏。
- 浅色与模拟深色模式：预览外层背景均为 `rgba(0, 0, 0, 0)`。
- 所有应用取消且开关为“不执行动作”：计数为零，空菜单预览禁用，没有占位项。

## 刷入确认

安装本版模块 ZIP 并重启，菜单组件日志应显示 v0.5.2。旧动作、已选应用与位置会保留。打开 WebUI → 你的快捷菜单，调整宽度、应用间距后保存。

本地测试不能代替目标手机上的窗口合成、触摸滚动和动画检查。本版需要确认：唤出时当前应用不再变暗、空项不显示、滑块变化生效，以及点击应用仍以 ColorOS 小窗打开。
