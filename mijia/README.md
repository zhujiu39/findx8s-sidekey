# 米家 Android 服务

此目录是独立运行的 GPL-3.0-or-later 组件，通过仅 Root 可访问的本地 Unix socket 与侧键模块通信。WebUI 和监听器不加载本目录的类。`module/lib/mijia.jar` 与 `module/lib/mijia-source.zip` 一起分发；后者提供本组件完整对应源码、构建脚本及测试。其余项目文件继续遵循根目录 MIT 许可，各组件权利以文件标记和第三方声明为准。

接口、扫码登录流程及规格解析移植自 [Do1e/mijia-api](https://github.com/Do1e/mijia-api)，版本 4.2.1，固定参考提交 `353363f79ea6f368461dc77c6de22d6f85623990`，原项目作者 Do1e 及其贡献者。修改日期：2026-09-23。移植范围：`apis.py` 的扫码、登录刷新、家庭/设备/场景和 MIOT 请求，`devices.py` 的规格提取，`miutils.py` 的请求签名与 RC4-drop1024。使用 Java/Android 内置网络与 JSON API，不打包 Python 解释器。原始 `miutils.py` 标记的 micloud/Sammy Svensson MIT 版权声明另行保留。

修改包括：独立 Android 进程、私有凭据存储、本地 IPC、请求队列、明确超时、响应大小限制、日志脱敏、属性类型/步长验证、写后读回、账号隔离和自动生成绑定编号。没有移植上游 MCP、CLI、账号密码登录或整个 Python 运行时。

## 构建和复现

1. 在仓库根目录运行 `python bootstrap_android.py`，获取固定版本并校验过的 JDK 21、Android API 35 和 Build Tools。
2. 运行 `python build_mijia.py`，进行 javac 和 D8 构建；显式添加 `--test` 才运行主机测试。输出在 `module/lib/`。Java 入口为 `cn.sidekey.mijia.MijiaMain`。
3. 可选 `python build_mijia.py --live`：匿名访问真实扫码端点验证握手和二维码读取，不登录账号、不保存二维码或凭据。此检查需要网络，不属于默认离线测试。
4. 整个模块使用 `python build.py`。构建用的 JSON 主机实现仅用于测试，固定 Maven URL 和 SHA256 见 `build_mijia.py`；Android 产物只使用手机自带的 `org.json`，不包含该 JAR。

## 运行和数据

- 目标 Android 15 / ARM64 / KernelSU。随 `service.sh` 启动，进程用 `setsid` 脱离侧键动作进程组，文件锁防止重复实例。模块禁用或移除后服务退出。不会开放 TCP 端口。
- 目录 `/data/adb/oppo_sidekey/mijia` 权限 0700；凭据、绑定、缓存和执行记录权限 0600，采用临时文件和原子替换；本地 socket 0600，并验证客户端和服务端 UID 为 0。
- HTTP 只使用 HTTPS，保留系统证书与主机名校验；允许米家登录/云 API 和规格站点地址，拒绝明文和自定义端口。跨域重定向不转发显式 Cookie。扫码图片由后台读取后作为 data URL 展示，WebUI 不接触登录令牌。
- 中国大陆账号；云 API `api.mijia.tech`、账号服务 `account.xiaomi.com`，与参考版本一致。公开设备规格来自 `home.miot-spec.com`；用同一规格 URN 从 `miot-spec.org` 补齐单位，失败时不猜测单位。规格缓存 schema 2，缓存 7 天，旧缓存自动重建。
- 本地请求是 4 字节大端长度加 UTF-8 JSON；请求上限 32 KiB，响应上限 2 MiB。网络任务单队列执行，最多排队 4 项，排队超过 60 秒不再发送。普通网络任务总预算 55 秒，连接 8 秒，单次读取 12 秒；扫码长轮询预算 150 秒。WebUI 轮询任务编号。
- 写入不会自动重试；网络中断返回“结果未知”，网关 code=1 表示受理，只有读回值一致才显示状态已确认。场景和动作回应不能证明所有设备的实际行为。
- 每个米家绑定属于创建它的账号；配置仅保存随机动作编号。退出会删除凭据和绑定；旧手势或菜单中的米家项需要重新设置。卸载模块删除私有数据。
- 公共 `status` 和错误消息不返回原始 HTTP 内容、认证地址、令牌或堆栈。设备/家庭名称只在本机显示和保存，不进入安装包。
- 快捷栏展开时通过 Root 本地 IPC 提交会话编号与绑定编号列表，服务批量读取 MIOT 可读布尔属性。点击米家动作使用 `menu-control` 直接提交到常驻服务，之后仅用 `menu-result` 获取本次任务结果；服务重启或响应中断不会重新提交控制。控制预算 35 秒，完成后有 15 秒状态读回预算，Root 本地等待最多 55 秒。
- 菜单展开时通过 `/v2/home/device_list_page` 按设备编号读取 `isOnline`，在线标志不使用家庭目录缓存，也不根据开关值推断。接口字段核对自[小米设备查询接口使用](https://github.com/XiaoMi/ha_xiaomi_home/blob/main/custom_components/xiaomi_home/miot/miot_cloud.py)。仅明确在线的设备读取开关属性；明确离线显示离线并禁用，缺失或查询失败显示未知。设备控制发送前再次检查在线状态，离线时不下发设置或动作。
- 操作完成后只刷新所操作设备的在线状态和可见开关属性，同设备绑定同步更新，其余返回增量保留标记。手动场景没有单一目标设备，操作后刷新可见设备一轮。布尔操作核对目标值，首次一致立即完成；不一致或属性未知时，以 250/500/1000/1500 ms 的间隔仅复查目标属性，最多补查 4 次，全部读取和等待共享 15 秒预算，可取消。不会重复发送控制。确认期间本地返回 `P`，达上限仍不一致时该属性的绑定显示在线但开关状态未确认，记录 `STATE_UNCONFIRMED`。
- 控制返回 `-704083036` / `-704053036` 表示设备操作超时，含义核对自[小米官方错误码表](https://github.com/XiaoMi/ha_xiaomi_home/blob/main/custom_components/xiaomi_home/miot/i18n/zh-Hans.json)。快捷栏布尔写入遇到这些码或请求中断时，保留目标值并复用上述有限次读回流程。读回一致只确认当前属性状态，原始控制错误码仍保留；未确认则结果为 `unknown`，不覆盖成 `STATE_UNCONFIRMED`。明确拒绝仍只刷新一轮，不重发。没有明确布尔目标的设备动作超时只报告未知结果。
- 空闲时不读取云端。在线开/关为 `1`/`0`，离线为 `o`，在线但属性未确认为 `u`，在线设备动作为 `a`，场景为 `n`，未知为 `?`。服务返回的 `-` 由 Root 合并为原值，不刷新未操作设备；菜单仅所选项进入等待态。本地通信失败只清除等待项，不重置其他设备。不把账号、设备编号或凭据送给菜单组件。
- `mijia-menu.log` 和 `mijia/debug.log` 记录本地提交、排队、发送、目标值、各次读回值及耗时，每个日志超过 32 KiB 时轮换，最多保留一份旧文件。WebUI 日常只展示末尾预览；“复制全部日志”额外读取各类日志和保留的上一段，每个文件上限 64 KiB，并注明截取。日志排除原始 HTTP 响应、凭据、完整设备编号和会话令牌；导出脚本只读取固定诊断文件。
- 发送设置前记录切换前布尔值、`siid` / `piid`、操作类型及布尔目标；发送后记录耗时、返回码和是否设备操作超时，便于区分控制慢与状态上报滞后。非布尔属性不记录具体值，异常不记录原文。
- “导出完整日志”通过独立的 MIT 日志组件和 Android [ACTION_CREATE_DOCUMENT](https://developer.android.com/training/data-storage/shared/documents-files#create-file) 选择目标文档，不需要让普通应用读取 Root 数据目录。Root 收集完整快照并提供只绑定 `127.0.0.1` 的临时服务；客户端必须持有本次随机 256-bit 令牌，不能指定源文件。长度与 SHA-256 校验、目标输出流关闭以及客户端保存回执全部完成后才显示成功。
- 完整导出不做每文件截取，总上限 64 MiB，超限明确失败；收集最多 20 秒、系统命令各 8 秒、选择位置最多 5 分钟、传输最多 60 秒。取消或结束后关闭会话、清理快照；结果文件私有保存并限制保留数量。完整日志仍只包含手机上现存的日志，已经轮换删除的历史不能恢复。

## 覆盖边界

支持扫码登录、家庭、家庭内设备、手动场景、MIOT 属性读写/布尔切换和参数明确的 MIOT 动作，以及通用只读数据卡片。没有 MIOT 规格的旧设备可通过米家 App 手动场景控制；不猜测 miIO 指令。云接口并非本模块拥有的稳定服务，服务端变化会导致兼容问题。构建通过和匿名握手通过均不代表已完成手机账号及真实设备的端到端验证。

## 只读数据

- `read` 绑定保存设备与 1～4 组 `siid/piid`，服务端按规格校验为只读且可读或可上报的标量属性。可写属性与带目标／设定语义的温度排除在测量卡片之外；温区来自服务名称，不按型号或固定属性编号适配。
- `/miotspec/prop/get` 的读数按设备和属性去重、每批最多 20 项，与开关读取共用一次展开快照。无控制请求；`run/trigger` 拒绝只读绑定，WebUI 手势列表不提供此类绑定。
- 在线标志独立获取。只读设备即使离线也尝试读取云端上报值，菜单明确标注“离线 · 上报值”；不表示数据刚刚采样。无返回、属性错误或非数值温度显示暂无数据，不使用目标值、零值或上次本地缓存补位。
- 每张卡片最多 384 字节 UTF-8。菜单状态新增 `r/s/q`，分别表示只读项在线／离线／在线状态未知。完成响应在 `D<状态>` 后附加 `|<十六进制读数>`，每个绑定一项；原有 `-` 同时保留其他设备的状态和读数。
- Android 菜单用带本次会话令牌的 `READINGS <offset>` 分页获取展示文本，每页 16 项；此接口只访问 Root 内存快照，不触发云端读取，不返回账号、设备编号或认证信息。只读卡片没有开关按钮，内容按可用宽度换行并可滚动。
